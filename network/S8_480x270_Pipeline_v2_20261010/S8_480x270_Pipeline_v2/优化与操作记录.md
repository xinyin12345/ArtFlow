# 480×270 CNN v2 修改与操作记录

本工程由 `style_s8_shared_480x270` 独立复制后修改，原版保留。冻结的 W8/A4/S8 网络、权重、偏置和尺度乘数没有修改。外部输入输出 480×270，内部反射补边到 480×272，RGB 只写前 270 行。

## 本次具体修改

1. 重写 `rtl/s8_shared.v` 的调度，分成窗口前端 fs、计算 cs、输出 qs 三个并发状态机。网络仍逐层执行，不是 22 层同时拥有独立计算引擎。
2. 普通窗口缓存改成 A/B 两组。计算单元持有一组时，前端可以准备另一组。full 标志在所有输出通道完成后释放，避免覆盖仍在使用的窗口。
3. 增加独立累加结果、主尺度、skip、目标地址、通道组的快照寄存器。MAC 开始下一组时，量化单元处理上一组，不再等量化和写回全部完成才重新计算。
4. 分离行反射计算、模 3 槽选择、缓存命中判断；列反射和字节地址也分拍。DW 地址不再在同一拍重新计算行反射、取模和访存地址。
5. 仲裁顺序为已完成的写回、残差 skip 读取、输入行读取。最多一个读请求未返回。新增命令锁存，ready 为低时地址、写数据、读写标志保持稳定，即使其他工作器产生更高优先级请求也不替换命令。
6. 利用最近邻 Up2 的特点：输出 3×3 DW 窗口最多对应输入的 2×2 个不同像素。每组源通道读取 4 个位置，记录九个 tap 到四个位置的映射，再送原来的九 tap MAC。卷积权重、九次乘积及中间 Q4 均保留，包含边界反射。
7. 下一窗口已经准备好时直接开始下一组计算，省去一次空闲调度。

`shared_mac.v`、`shared_quant.v`、`shared_line.v` 的数值实现沿用原版；主要新增逻辑在顶层调度、缓冲、DW 映射和访存仲裁。MAC 仍使用 96 DSP，四路量化使用 24 DSP，地址/控制使用 1 DSP。

## 本次遇到的问题及处理

- 直接将旧实现的时钟约束改成 150 MHz 不足以证明可用。本次先修改逻辑与控制路径，重新综合、布局布线，检查真实 setup/hold 余量。最终分析最高频率约 167.029 MHz，交付仍按约 150 MHz 约束，未使用分析极限频率。
- 第一轮条件帧率仅约 15.33 fps，余量较少。针对 DW 读取重复源像素的问题改成四位置缓存，将控制周期进一步降低到 8,631,903。
- 多工作器的优先级会变化，可能在 ready 为低时替换地址。新增命令锁存，并在测试台检查整个背压期间命令稳定。
- 并发计算时，量化可能读到被下一组覆盖的累加值或尺度。改成完整结果快照；缓冲未空时计算端保持结果并反压。
- Efinity 在中文目录下的工具运行、旧 Python 的路径解析存在执行环境限制。工具在独立 ASCII 临时目录工作，结果复制回工程；未更改安装目录或系统配置。
- 综合报告存在位宽截断和 RAM 映射提示。地址、通道、tap 和尺寸范围按固定网络审查；S20 累加的最大绝对值界 365,775，小于 524,287。小 DW 缓存因异步多路读取映射为逻辑，这是有意用较充裕的 XLR 换取并行数据选择；参数 ROM 中的常零部分被工具优化。保留原始警告日志供复查。
- DDR 延迟敏感性仍存在：每次读取 10 周期时，控制仿真为 12,985,965 周期，约 11.55 fps。当前逻辑口仍是单未完成读请求，没有实现板级 DDR 突发桥；17.38 fps 只适用于列明的较快逻辑接口条件。

## 如何在 Efinity 手动复现

1. 把交付工程解压到英文路径，例如 `C:\fpga\s8_v2`。不要将多个版本的顶层同时加入项目。
2. 打开 `s8_shared.xml`，确认器件 Ti60F225、时序等级 I3、顶层 `s8_shared`。
3. 工程只编译 `s8_shared_flat.v`。它已包含四个模块和层配置；`rtl` 文件夹用于阅读和修改，不能再与平铺文件重复加入。
4. 确认 `mem` 三个参数文件相对路径可读，SDC 使用 `clock.sdc`，周期为 6.667 ns。
5. 本次综合通过命令行额外使用 `max_mult=150`、`max-bit-blast-mem-size=16384`。若 GUI 未保留这些选项，先用 `run_efinity.py --flow map --period 6.667` 复现；脚本保留完整命令和日志，不依赖猜测 GUI 默认值。
6. 依次执行综合、布局布线。检查资源表以及最终 `s8_shared.timing.rpt`，setup、hold 不能为负。不能仅根据流程显示 PASS 判定时序达标。
7. 这还是独立 CNN 核工程，外部端口是供系统内部连接的逻辑端口，没有提供板级引脚绑定、DDR 控制器、视频接口或 PLL 实例。不可直接把这些逻辑端口分配到 F225 全部物理引脚或认为此工程可直接上板显示。
8. 接入视频工程后重新约束 CNN/DDR/视频时钟、跨时钟接口和复位，重新综合及布局布线。当前单时钟 CDC 报告不能替代整系统 CDC 验证。

如果修改了 RTL，先运行 generate.py 更新平铺文件，再做回归和综合。run_efinity.py 的 pnr 会核对源文件和 ROM 与指定 map 暂存目录一致，拒绝将新 RTL 与旧网表混用。
