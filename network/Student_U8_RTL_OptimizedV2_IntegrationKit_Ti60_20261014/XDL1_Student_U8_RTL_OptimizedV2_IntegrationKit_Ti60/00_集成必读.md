## 1. 从哪些文件开始

1. 先阅读本文件。
2. 集成推荐使用根目录`student_u8_flat.v`，顶层为`student_u8`，默认参数`EXT_W=480, EXT_H=270`。它已展开层配置及所有子模块，与实际综合输入一致。
3. 保留根目录`mem/`四份文件：`shared_weights.mem`、`shared_bias.mem`、`shared_main.mem`、`shared_beta.mem`。它们由RTL中的`$readmemh("mem/...")`加载，综合初始化进入器件配置。
4. `rtl/`是相同版本的模块化源码。若选择它，添加六个`.v`并把`rtl/`加入include搜索目录，以找到`layer_config.vh`。
5. **扁平源码与模块化源码二选一**。不要同时把根目录扁平文件、`rtl/`、`baseline/rtl/`或`reports/`内网表加入工程，否则会出现重定义或混入旧实现。
6. `student_u8.xml`、`clock.sdc`是独立核心的Efinity参考工程。整机中例化`student_u8`并使用整机顶层，不是把它继续作为整机顶层。
7. `sources_flat.f`、`sources_modular.f`为相对路径文件清单，供整理源文件或支持`-f`的仿真工具使用；Efinity直接使用XML工程或手工添加上述文件。

推荐解压到英文目录。在包根目录打开参考工程或启动仿真，确保相对`mem/`路径可解析。若整机工具工作目录不同，在工程中配置或放置相应ROM路径；修改初始化路径后需重新核对内容并重跑构建，不改变参数内容。

## 2. 核心端口

| 端口 | 方向/位宽 | 合同 |
|---|---|---|
| clk | 输入1 | 全核心单时钟，参考约150 MHz |
| rst | 输入1 | 高有效、同步复位；在clk上升沿采样 |
| start | 输入1 | 空闲时给1拍脉冲；输入帧必须已写完且可见 |
| busy | 输出1 | 核心正在运行 |
| done | 输出1 | 最后一层结束时的1拍脉冲 |
| mem_valid | 输出1 | 当前有有效读/写命令 |
| mem_write | 输出1 | 1写、0读 |
| mem_addr | 输出24 | **字节地址**，相对CNN工作区基址，8字节对齐 |
| mem_wdata | 输出64 | 写数据；读命令时忽略 |
| mem_wstrb | 输出8 | 当前为8'hFF，8个字节全部有效 |
| mem_ready | 输入1 | 下游能接受当前命令；valid和ready同拍为1才接受 |
| mem_rvalid | 输入1 | 一条已接受读命令的响应有效 |
| mem_rdata | 输入64 | 与rvalid同拍的读数据 |
| layer_done | 输出1 | 层结束调试脉冲 |
| layer_index | 输出5 | 当前层索引；非末层layer_done脉冲期间已递增到下一层 |
| frame_cycles | 输出32 | start到done的核心计数，运行时累加 |

不要把字节地址再次乘8。核心已经包含握手期间的命令锁存：ready为0时保持valid、地址、类型和写数据。

## 3. DDR桥必须满足的行为

- 当前最多一个未完成读；桥只对实际接受的读返回一次rvalid，数据必须正确对应。
- 读响应不得在命令接受的同一拍返回，至少晚1个时钟。rvalid没有反压端口，响应到达时核心会消费。
- 有读未返回时，仍可能出现写命令。桥若无法接受，拉低ready；不能丢弃已经接受的命令。
- 写命令的ready意味着桥已可靠接收该写，不是随意确认。若内部排队，必须维持写后读顺序与可见性，不能让下一层读到旧数据。
- 核心done表示所有结果写命令已被接口接受。若桥仍有未提交写，发布结果给显示或CPU前，还需等待桥写队列及AXI写响应排空。
- 复位时同步处理桥状态，丢弃/排空旧事务，避免复位后收到上一任务的迟到rvalid。

### 对接现有128位AXI时

核心的64位逻辑口不是AXI口，需增加协议桥。不能直接接到128位AXI信号上。

- 系统字节地址=`CNN_BASE + zero_extend(mem_addr)`。建议CNN_BASE按2 MiB对齐，保留完整6 MiB范围，并与采集/显示帧区隔离。
- 如果桥使用16字节对齐的128位访问，则AXI地址清低4位；原64位地址的bit3决定使用低64位还是高64位。
- 读返回从128位数据中选正确的一半，生成一次64位rvalid。
- 写时按bit3放置64位数据，16位WSTRB对应为`16'h00FF`或`16'hFF00`；不得覆盖另一半64位数据。也可使用控制器支持的合法窄传输方案，但需遵循其AXI合同。
- AR/R、AW/W/B各通道分别握手，核心ready不能简单等于其中一根AXI ready。
- 若DDR AXI与CNN不在同一时钟域，使用完整命令/响应CDC或异步FIFO，不可对多位地址/数据逐位两拍同步。

本包提供核心和接入合同，**未附已验证的64→128 AXI桥**。桥必须按实际整机接口实现与仿真。

## 4. DDR工作区与图像格式

三个2 MiB槽，总预留6 MiB：

| 槽 | 相对起始地址 | 用途 |
|---|---:|---|
| 0 | 0x000000 | 启动输入，运行中复用 |
| 1 | 0x200000 | 中间特征，最终RGB输出 |
| 2 | 0x400000 | 残差中间特征 |

输入：480×270，逐行、逐像素，每像素8字节，低字节起依次`R,G,B,0,0,0,0,0`。地址=`CNN_BASE+(y*480+x)*8`，整帧1036800字节。不能直接输入32位XRGB/BGR帧；需要转换布局并保持颜色顺序。

底部反射补2行由核心读取端完成，不必在DDR额外写272行。内部特征NHWC，通道补到8的倍数；U8/S8每通道1字节，S12符号扩展成小端16位。具体逐层描述在architecture.json，不应改通道布局或将S12截成8位。

最终RGB只写480×270，位于`CNN_BASE+0x200000`，同样每像素8字节、低三字节RGB。三槽运行中会覆盖，输入槽不是保留原图的永久帧缓冲；整机若需原图对照显示，应在其他区域保存。

## 5. 时钟、复位与启动

- 核心没有内部PLL。系统提供clk，参考约150 MHz。
- 独立SDC只有`create_clock -name clk -period 6.667 [get_ports {clk}]`。整机应按实际PLL和时钟关系配置约束，不要机械把参考顶层端口约束复制到不存在的整机端口。
- 外部异步复位需在CNN域正确处理，再提供同步高有效rst。不能仅因系统其他模块低有效就直接连反相/跨域信号而不处理释放时序。
- start只在busy=0时给1拍；跨域控制用握手传递。确保输入DMA及桥写已完成再启动。
- 运行中不替换权重，不覆盖三槽。得到done并确认桥排空后，才能发布输出或装入下一帧输入。

## 8. 整机集成后需要重新检查

1. 先用固定输入验证桥返回的64位数据、字节序、选半和写掩码，保持ready反压与读响应合同。
2. 比对19层写回地址/数据或先比对最终RGB，参考模型在`reference/integer/`，推理入口`infer_integer.py`。
3. 验证两帧连续运行、长延迟和随机ready停顿；done后等桥排空再读取输出。
4. 在完整视频顶层重新综合和布局布线，检查真实DDR桥、FIFO、CDC、PLL、I/O和整机资源。
5. 再进行上板固定图读回、连续视频和实测帧率。

这些步骤属于集成工作，本包没有把其标记为已完成。参考工程不是可直接烧录的完整摄像头系统。
