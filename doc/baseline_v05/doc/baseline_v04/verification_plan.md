# v04 验证计划

## 范围

实际 `cam_fb_pipe` RTL，包括 Bayer 合并、三缓冲、AXI 调度、双窗口及 HDMI 像素时序。CSI 输入与 DDR 是事务模型；DDR PHY/电气与显示接收器需实板。沿用 Questa SystemVerilog 自检环境，不引入 UVM；UVM_ERROR/UVM_FATAL 指标不适用。

抓帧位于 `cam_fb_pipe` 输出、Gamma 之前。Gamma 和测试图分别单测；没有把摄像头电气接口、开机色条切换、Gamma、HDMI 编码/串行器串成一个全顶层仿真。全工程 Efinity 实现另行验证可综合性与约束内时序。

## 检查方法

- 摄像头每帧变化，前 8 个合并像素编码完整 32 位帧号；scoreboard 关联捕获、发布和读出事件，并逐像素检查。不是纯黑盒验证。
- 每个 bank 发布时检查所有 DDR 像素和帧身份，要求三个 bank 全部命中；B 完成前不可发布、RLAST 前不可释放，读写 bank 不相撞。
- 左右两窗每个像素与同一输入帧的 Python 黄金图一致，上下背景必须全黑；全分辨率检查 1920×1080 全部像素。冻结、倒退、错行和窗口边界错误均失败。
- AXI 断言检查五通道反压稳定性、WLAST、4 KB 边界和未知值；全局 outstanding 不大于 1。调度器单测检查紧急优先、两次服务后必须让步、随机事务耗时、请求撤销和事务中复位。
- 正常运行出现黑尾/错误像素立即失败。人为拥塞或 RRESP 错误只允许正确前缀及后续全黑，不允许恢复非黑片段或忽略错误像素；故障撤销后恢复完整帧。
- 缺失/X 黄金文件、错误启动像素、冻结画面、右窗口损坏、黑边损坏及非法几何必须触发指定 Fatal，证明验证器能拒绝错误。
- 1000 连续小尺寸完整帧测试检查持续轮转与更新；记录实际模拟时长，明确不等于 30 分钟实板或 108000 个真实 60 Hz 帧。
- Efinity 正常 SDC 的 setup/hold 每条已报告时钟关系必须非负且包含活动时钟。Gray CDC 审计检查两个 32 位总线全部端点、skew 和慢角延迟不超过 2.5 ns。审计副本 SDC 不用于正常时序签核。

## 通过条件与证据

正向仿真要求进程退出码 0、存在最终 PASS、无 Warning/Error/Fatal/FAIL。负向用例要求指定 Fatal 且无最终 PASS。保存原始日志、配置、源码 SHA-256、抓帧和独立 Python 比对。

综合、接口、布局布线、比特流、正常时序与 CDC 分别记录结果。最终交付指纹覆盖源文件、证据和比特流。没有采集 RTL 行/分支/翻转覆盖率，不报告 100% 覆盖率。硬件验收状态始终单列。
