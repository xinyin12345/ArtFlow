# 赛题一 ArtFlow 版本开发计划（基于第二版架构）

> 架构基线：SC431HAI 1920×1080 RAW8（BGGR）→ 2×2 Bayer 合并 → 960×540 RGB 写 DDR → 加速器 480×270 CNN（100 MHz）→ 放大回 960×540 → 1080p60 左右对比显示。
> 版本目录沿用 `D:\work\FPGA\ArtFlow\Process\ArtFlow_vXX`，每个版本上板验收通过后再复制出下一个版本。
> 每个版本都要留下：综合资源报告、时序报告、上板照片或视频、一段"本版改了什么 / 遇到的问题"记录。

## v02_cleanup —— 清理与颜色校验
**目标**：在不改变功能的前提下腾出资源，并把颜色通道顺序确认清楚。

任务：
1. 把 `gamma_correction` 改成三路同步 ROM 查表（R/G/B 各一块），保持原来的查表内容和同步延迟。
2. 删掉 VIO，把逻辑分析仪的探针数和采样深度压到最小（只留当前要看的信号）。
3. 在显示端加一个测试图模式（红 / 绿 / 蓝 / 白 / 灰阶色条），用来确认 R、B 没有接反。现有 Gamma 分支和旁路分支的 R/B 接线顺序不同，这一步要查清楚。
4. 跑综合，记录资源基线。

验收：
- 画面与 v01 一致，色条颜色正确。
- 逻辑单元从 30,793 降到约 17,000~20,000（Gamma 那部分应减掉约 1 万）。

## v03_capture_rgb —— 新采集链路
**目标**：DDR 里存的从 RAW 变成 960×540 RGB。

v03a（仿真先行）：
1. 写 `bayer_half_rgb`：输入每拍 4 个 RAW8 样本，BGGR 相位可配置（参数或寄存器），一行 RAW 行缓存，第二行期间每拍输出 2 个 RGB。
2. 写 `cdc_line_fifo`：MIPI 像素时钟 → 100 MHz `core_clk`，深度一行（960×24 bit），2 像素/拍转 1 像素/拍。
3. 写 `color_lut ×3`：256 项 × 8 bit，先用固定初值（白平衡增益 × Gamma），预留写端口。
4. Python 写参考模型：输入一帧 RAW 文件，输出 960×540 RGB；测试平台逐像素比对。

v03b（上板）：
1. 写 `cam_wr_dma`：960×540 RGB（32 bit 打包）按 AXI 突发写入 DDR，先用单缓冲。
2. 写一个最简 `video_rd_dma` + 窗口逻辑：沿用 demo 的 1080p 时序，把 960×540 显示在屏幕左半边。
3. 替换掉原来的 `checker0`（frame_buffer）和 `debayer_top`。

验收：
- 仿真逐像素比对通过。
- 上板实时画面颜色正确、比例正确（16:9 不变形）；单缓冲允许偶尔撕裂。
- 摄像头输出 1920×1080 与寄存器配置一致。

## v04_buffer_display —— 三缓冲、帧管理、双窗口
**目标**：采集与显示解耦，不撕裂、不欠载，AXI 结构定型。

任务：
1. `frame_manager`：原画池 3 块，维护 frame_id 与占用状态；写完才发布，显示只在场消隐期间换地址，正在被读的帧不会被覆盖。
2. `axi_arbiter`：写仲裁 2 路（采集 + 预留给 AI 结果），读仲裁 3 路（预留 AI 读 + 显示左 + 显示右），显示读优先；预留的端口先接空。
3. `video_rd_dma ×2` + `compositor`：左右各 960×540，上下黑边由逻辑生成，不读 DDR。
4. 统计计数器：采集完成帧数、显示欠载次数、FIFO 溢出次数（先接逻辑分析仪或 LED 观察）。
5. 实测带宽：观察显示 FIFO 最低水位。

验收：
- 左右两边同时显示实时原画，挥手快速运动时无撕裂。
- 连续运行 30 分钟，欠载与溢出计数为 0。

## v05_soc —— Sapphire SoC 与寄存器
**目标**：RISC-V 接管配置工作。

任务：
1. IP Catalog 生成 Sapphire SoC：单核、32 KB 片上 RAM、小缓存、不接 DDR；外设 UART、I2C、GPIO、APB3 Slave；中断输入预留给加速器。
2. 用 Hard JTAG（User TAP）调试，注意和逻辑分析仪共用 JTAG 时的冲突。
3. 写 `apb_reg_bank`：版本号、控制 / 状态、color_lut 写口、显示模式、统计计数读取。
4. 固件 C1：UART 打印、读版本寄存器。
5. 固件 C2：用 I2C 按 `注意要点.md` 的寄存器表初始化 SC431HAI，删除 `i2c_master_ctrl_top`。
6. 固件 C3：写 color_lut（可调白平衡 / Gamma），串口命令调整增益。

验收：
- 上电后由 RISC-V 完成摄像头配置并出图。
- 串口能读计数器、能改白平衡且实时生效。
- 核对 PLL 仍为 4 个、全局时钟余量足够；记录 SoC 实际资源。

## v07_accel_shell —— 加速器外壳（直通）
**目标**：先打通"DDR 读 → 处理 → DDR 写 → 显示"整条数据链路，里面不放网络。

任务：
1. `axi_rd_dma`：从 frame_manager 领取并锁定最新原画 original[n]，处理完释放。
2. `down2x`（2×2 平均 → 480×270）→ 直通 → `up2x`（双线性 → 960×540）→ `axi_wr_dma` 写入风格池 styled[n]。
3. `accel_ctrl`：启动 / 完成中断接 PLIC；风格池 3 块，写完才发布。
4. 硬件统计：推理完成帧数、主动跳过帧数。
5. 固件 C5：中断驱动的调度循环；OSD 同时显示"采集 FPS / 处理 FPS"。

验收：
- 右窗口显示降采样再放大的画面（略模糊），无撕裂、无错行。
- 处理 FPS 接近 30（直通时应不受算力限制）。
- up2x 用 Python 参考模型逐像素比对通过。

## v08_conv_unit —— 单层卷积单元
**目标**：做出可复用的 INT8 卷积层，并拿到真实资源和频率。

任务：
1. `conv_layer` 参数化模块：输入通道数、输出通道数、乘加并行度、图像宽度全部可配；包含行缓存（2 行）、3×3 窗口、乘加阵列、INT32 累加、逐通道定点缩放（BN 已折进权重和偏置）、ReLU / 末层 clip、饱和到 INT8。
2. 先放一个 3→3 固定核（模糊或锐化）进 v07 的直通位置上板，验证数据通路。
3. 单独综合一个 8→8、24 路乘加的实例：记录 DSP、逻辑、存储、fmax；确认 DSP 是否能一块做两个 8 位乘法。
4. B 线同步提供该层的测试向量，RTL 与 Python 定点模型逐比特一致。

验收：逐比特一致；单层 8→8 在 100 MHz 下每像素 24 周期；根据实测修正资源预算表。

## v09_cnn_int8 —— 完整 4 层网络
**目标**：真正的风格化上屏，基础要求功能齐全。

任务：
1. `cnn_core`：3→8、8→8、8→8、8→3 四层级联，乘加分配 9 / 24 / 24 / 12，层间握手，行流水。
2. `weight_bank`：由 RISC-V 经 APB 写入；固件 C6 从 C 数组加载一套风格权重。
3. 用 B 线训练好的第一种风格权重上板。
4. 测试注入模式：在采集端注入固定测试图（或色条），硬件结果写回 DDR 后由固件分段读出校验和，与 Python 模型比对。

验收：
- 右窗口为实时风格化画面，处理 FPS 稳定 ≥ 15（目标 25 左右）。
- 测试图的结果与 Python 定点模型逐比特一致。

## v11_multi_style —— 多风格切换（高阶 1）
任务：
1. `weight_bank` 双套（或三套）常驻；风格选择寄存器只在任务开始时锁存。
2. 按键和串口命令切换风格；OSD 显示风格名。
3. 测量切换延迟：从按键到屏幕出现新风格的时间（用计数器记录各阶段时间戳），目标 < 100 ms。

验收：至少 2 种风格，切换 < 100 ms，不重启、不重配 FPGA。

## v13_network_upgrade —— 网络升级
依据 B 线的对比结果二选一或组合：
- 16 通道 4 层（约 15 fps 上限，需约 130 路乘加）；
- 8 通道 6 层 / 12 通道 4 层（30 fps 左右）；
- 可选：带运动门控的时域平滑（EMA），切风格和场景突变时清零。

注意：先核对存储块预算，升级网络时存储块比 DSP 更先吃紧。

验收：画质主观提升明显，FPS 仍 ≥ 15，资源不超预算表。

## v14_720p —— 1280×720 采集与处理（高阶 2）
任务：
1. 摄像头窗口改回 2560×1440，`bayer_half_rgb` 直接输出 1280×720（前端结构不变）。
2. 帧缓存尺寸、DMA 地址、行缓存宽度全部参数化到 1280。
3. 网络输入 640×360，放大回 1280×720；重新核算帧率和存储。
4. 显示：对比模式下缩放到 960×540，或全屏模式显示 1280×720（需加显示端缩放或居中）。
5. 核对 MIPI 带宽、DDR 带宽实测余量。

验收：1280×720 @30 采集，风格化帧率满足目标。
