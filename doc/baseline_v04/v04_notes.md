# ArtFlow v04 设计说明

基线：`../v03`，Git HEAD `5fe59e1d3aab8dac9a1af9d590a3066795ddd330`。v03 保持原样。v04 是独立目录；历史报告保存在 `baseline_v03/`，不能用作当前版本的通过证据。

## 显示布局

输出保持 1920×1080、2200×1125 总时序、148.5 MHz 像素时钟。两窗口为：

| 区域 | X | Y | 大小 |
|---|---:|---:|---:|
| 左窗口 | 0 | 270 | 960×540 |
| 右窗口 | 960 | 270 | 960×540 |
| 上、下背景 | 0 | 0 / 810 | 1920×270，各自全黑 |

坐标从有效显示区左上角开始。左右窗口均为同一已发布帧的原尺寸 RGB；右窗当前是旁路预览，不是已经实现的 CNN/风格化输出。后续算法接入点是 `rgb_frame_store.v` 中右窗口 `line_q` 输出分支。未来独立算法帧还需增加帧号配对、bank 所有权和完成握手，当前不能直接接任意异步图像。

左窗口从 DDR 流取像素，同时写入一行 BRAM；右窗口复读该行。因此每个显示帧只读 960×540×4=2,073,600 字节；两窗不会使 DDR 读取量翻倍。30 fps 写入约 62.208 MB/s，60 Hz 读出约 124.416 MB/s，合计有效负载 186.624 MB/s，均为十进制 MB，不含 DDR 刷新、命令及周转开销。

唯一板级配置仍是 `rtl/ArtFlow_top.v`。`CFG_DUAL_WINDOW=1` 启用上述布局；`0` 保留 v03 的二倍全屏放大。摄像头输入、RAW 2×2 合并、增益、Bayer 相位、Gamma 和开机色条配置沿用 v03。外部半速 porch 接口保留，双窗口在包装器内将水平时序乘二，帧缓存显示域在编译时选择 HDMI 像素时钟；不是运行时切换时钟。

## 三缓冲与帧管理

继续使用三个 4 MiB bank：`0x00000000`、`0x00400000`、`0x00800000`。每像素小端 XRGB8888，地址 `bank+(y*960+x)*4`。只有捕获完成、长度正确、无溢出、所有 AXI B 响应成功才发布。读 bank 从帧请求到最后 RLAST 被固定，写入避开最新完整 bank 和正在读取的 bank。

一个输出 epoch 只选择一个完整帧；窗口、左右边界和背景切换均不重新选帧。停摄像头后重复最近完整帧；新帧恢复后继续更新。允许丢弃来不及捕获的输入帧，不是无损录像接口。

## AXI 突发调度

新增 `video_axi_scheduler.v`。写请求必须已缓存整个突发；读请求必须有足够 FIFO 空位。以突发为单位分配端口，直到 B 或 RLAST 完成才重新仲裁，全局最多一个未完成突发。AW/AR 等待握手期间不得撤回 VALID，已接受 W/R 不被抢占。

读 FIFO 少于 1/4 时读紧急，写 FIFO 至少 3/4 时写紧急。仅一侧紧急时优先它；同等级时轮换。即使紧急请求持续，连续服务同一侧最多两次后也必须服务持续等待的另一侧。这个上界按完成的事务计数；DDR 从机无限停顿时不承诺有限周期完成。

串行突发牺牲部分并行度来明确读写服务顺序；现有 1024×128 bit FIFO 为 128-beat 突发提供余量。受控反压和实际 1080p 帧率需分别验证。严重阻塞或 RRESP 错误时仍保持显示时序，错误位置之后输出黑色直到下一帧；这类故障恢复行为不能算“零断流”验收通过。

## 时钟与复位

捕获完成、计数和显示 epoch 继承 v03 的 toggle / 注册 Gray 同步及各域同步释放。正常 SDC 将同源 HDMI/半速显示时钟归入同一显示组，并与 AXI、CSI 时钟隔离；HDMI 慢/快时钟之间仍分析时序。两条 Gray 总线继续执行路由后 32+32 端点的 2.5 ns skew/data-delay 审计。

全局复位必须同时复位 AXI 主从。不能用摄像头帧头或显示帧头复位正在进行的 AXI 事务。运行期间不改变几何、Bayer 相位或增益。
