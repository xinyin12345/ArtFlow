# v05 APB3 控制寄存器

接口兼容 v05。当前 v06 白平衡改善版由 `ArtFlow_top` 覆盖控制模块参数，三个通道的板级复位值均为 102（Q8.8），与固件 `defaults` 一致。

`artflow_control` 使用 100 MHz APB 时钟与 50 MHz CSI 像素时钟。下表地址为 SoC 外部 APB 窗口内的字节偏移，所有访问必须为 32 位、4 字节对齐。

| 偏移 | 名称 | 属性 | 内容/复位值 |
| --- | --- | --- | --- |
| 0x00 | ID | RO | `0x41524605` |
| 0x04 | STATUS | RO | bit0 提交忙；bit1 DDR 校准完成（两级同步）；bit2 摄像头已配置；bit3 摄像头复位有效 |
| 0x10 | SHADOW_R | RW | 红增益，Q8.8，板级默认 102 |
| 0x14 | SHADOW_G | RW | 绿增益，Q8.8，板级默认 102 |
| 0x18 | SHADOW_B | RW | 蓝增益，Q8.8，板级默认 102 |
| 0x1c | COMMIT | RW | 写 1 提交整组影子；读 bit0 返回忙 |
| 0x20 | ACTIVE_R | RO | 已完成提交的红增益 |
| 0x24 | ACTIVE_G | RO | 已完成提交的绿增益 |
| 0x28 | ACTIVE_B | RO | 已完成提交的蓝增益 |
| 0x30 | CAMERA | RW | bit0 复位有效，bit1 已配置；复位值 1 |

增益仅接受 0..1024，即 0..4.0 倍。32 位写入值的高位也参与范围检查，不能通过截断绕过限制。CAMERA 仅接受 0（释放复位、未配置）、1（保持复位、未配置）、2（释放复位、已配置）；同时置位与保留位置位均报错。

PREADY 恒为 1。非法地址、非字对齐、向只读寄存器写入、增益超范围、COMMIT 写非 1 或忙时再次提交均在 APB access 阶段返回 PSLVERROR，没有写入副作用。非法地址读回 0。setup 阶段不产生任何写操作或错误响应。软件必须先检查 STATUS.busy，再提交；忙时仍可调整下一次的影子值。

## 提交与帧边界

COMMIT 把整组三色影子复制到独立 mailbox 并翻转请求。payload 在接收确认返回前保持稳定，请求和确认各用两级单比特同步器。像素端仅在 VS 任意边沿打开的消隐窗口内应用整组值，且要求 HS/valid 均低、最近五拍没有有效输入，使已有 Bayer 五级流水线排空。窗口在首个 HS 或 valid 关闭，行间长消隐不能打开窗口。上电到首次输入之间也允许提交；若摄像头在帧中停住，则提交保持忙，直到下一次合格帧边界或系统复位。

如果 VS 边沿和数据过近、无法排空流水线，提交安全地延后到下一次合格边界。现有 `bayer_bin2x2` 的输入接口、运算和延迟均不改变。CAMERA 操作不隐式提交增益，不复位 mailbox。

ACTIVE 三色值是 APB 域确认镜像。busy 清零与镜像更新发生在同一拍；软件等待 busy 清零即可读取一致的整组结果。尚在 busy 时 ACTIVE 保持上一次完成提交的值，即使像素端刚刚更新、确认仍在跨域途中。

## 复位及集成要求

`presetn` 与 `pixel_resetn` 必须由同一个系统异步复位同时拉低，各域可以独立同步释放。只复位 mailbox 的一侧不受支持。摄像头的 CAMERA.reset 和 configured 状态不能用于单侧复位此模块；如需跨域使用 `camera_ready`，由使用端两级同步。摄像头复位输出在 APB 域、上电默认有效，防止固件尚未启动时摄像头开始发送未配置数据。

控制接口新增的多位跨域路径是 mailbox→gain 寄存器，其稳定性由请求/确认握手保证，不能简单将影子寄存器直接跨域接入像素模块。实现约束应覆盖这条 payload 路径，并检查请求/确认同步器级间路径仍按各自时钟分析。

Efinity MAP 将 gain 输出寄存器命名为顶层 `camera_gain_r/g/b[n]~FF`，mailbox 保留 `u_control/mailbox_r/g/b[n]~FF`。SDC 与 CDC 审计使用这些实际名称，并要求 48 条逐位连接完整存在；逻辑模块内的 `u_control/gain_*` 不是此综合网表的寄存器名称。
