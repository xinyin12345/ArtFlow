# v09 性能候选验证计划

目标：保持原训练模型、图像尺寸、颜色合同和视频接口，在 222.222 MHz 独立 CNN 时钟下通过实际综合/布局/时序，并在完整尺寸带视频争用的 RTL 仿真中每帧 >15 FPS，最后交用户验证实板。不得用单核周期数替代整个处理链路时间。

| 优先级/特性 | 刺激与用例 | 检查器及必需证据 |
|---|---|---|
| P0 算术与顺序 | 960×540、连续 2 帧；64×44 多帧随机输入 | 原 NumPy 整数模型逐像素/逐层特征/地址 scoreboard，所有 feature 写入和最终输出全部检查 |
| P0 性能 | 222.222 MHz CNN，100 MHz AXI；视频优先 mux，约 320 MB/s 后台流量 | 100 MHz 作业墙钟计数，2 帧分别 >15 FPS；后台带宽实际计数达标 |
| P0 CDC 数据安全 | 双向 FIFO、随机背压、多个非整数时钟比、运行中公共复位 | 完整顺序/数据、stall 稳定性、满队列背压、排空后读写数量一致；ILA/板测尚不代替仿真 |
| P0 CDC 物理实现 | 正常布局布线后的全部 CNN/core 跨域端点 | 时钟组关闭的独立审计；46 个 Gray 位、全部 payload 端点、三级复位链；Gray 4.5 ns、payload 8 ns 路径预算；同步器第二级 setup/hold 正常计时 |
| P0 发布与帧所有权 | 原采集/显示帧池 + 真实 CNN + APB IRQ，缩小几何 | 不覆盖源/显示 bank；源准备完成后释放；最终 B 之后才发布；完整显示快照；IRQ 数与完成帧一致 |
| P0 总线故障 | 准备 R/B、CNN R/B 错误各 2 帧 | 错误跨域返回；failed 帧不发布；控制层拒发与下一帧恢复用例 |
| P0 时钟与资源 | Efinity 2026.1.132、Ti60F225 I3、正常 SDC | 实际 PLL 输出 222.222 MHz，其他板级配置完全匹配基线；全时钟 setup/hold 非负；RAM/DSP 不超限 |
| P1 边界和等待 | 64×44、60% 等待、首拍 48 周期、CNN 半周期 2.7 ns、3 帧 | 四态仿真比对；覆盖 4 KiB 边界、网络补行、缓存行重用、随机通道背压 |
| P1 CPU/PLIC | 实际固件在原 Sapphire 模型执行；摄像头成功/NACK 与定时完成外设 | 相机 I2C 回读、UART 白平衡、PLIC claim/ACK；不把外设 fixture 当作真实 CNN |
| P1 颜色/控制兼容 | 原 Gamma 标记、控制器及固件主机回归 | 像素与标记对齐、APB 错误、IRQ W1C、skip/error，4 组固件测试 |

所有采用的结果必须带源码与日志 SHA-256，且与发布位流输入快照一致。源文件在长仿真运行期间改变时，该次报告不得用于当前交付，即使旧 VVP 的算术检查通过。中间失败产物不更新 `outflow/ArtFlow.bit`。

工具：完整尺寸使用 Questa 2025.3，其他四态回归使用 Icarus；无 UVM/功能覆盖率数据库。Icarus 代码生成后的退出故障独立标记，VVP 必须正常完成。Questa 的 Windows 沙箱 DLL 启动问题已定位，使用正常本机环境与已有合法许可顺序执行 CPU/CNN 回归。真实 Sapphire CPU 测试保留厂商加密模型，定时完成外设仅用于验证固件/PLIC；真实 CNN 数据面由其他回归覆盖。Efinity 安装与许可证不修改。

实板验收：用户下载后记录 CAP/PRC 和两次串口状态，检查真实输入帧率、DDR 争用/刷新和固件中断开销下的处理帧率，连续至少 30 分钟观察图像和温升。此项完成之前不宣称“板上稳定 >15 FPS 已验收”。

本轮执行边界：P1 CPU/PLIC 补测在摄像头初始化期间主动中止，未计作通过。既有固件未改，主机测试通过不能代替完整 CPU 联调；此项在最终结果中单独列为待完成。
